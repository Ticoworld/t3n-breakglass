# C-0 Terminal 3 Primitive Archaeology

Research date/retrieval date: 2026-09-01. Evidence is separated into official source claims, local SDK declarations, and BreakGlass usage. The local installed SDK is `@terminal3/t3n-sdk 5.2.0`; the contract pins host WIT packages at `2.1.0` and tenant context `1.0.0`.

Primary sources: [T3N docs index](https://docs.terminal3.io/llms.txt), [host API](https://docs.terminal3.io/t3n/how-t3n-works/host-api), [TEE model](https://docs.terminal3.io/t3n/how-t3n-works/tees), [consensus](https://docs.terminal3.io/t3n/how-t3n-works/consensus), [z namespace](https://docs.terminal3.io/t3n/how-t3n-works/z-namespace), [ADK agent auth](https://docs.terminal3.io/developers/adk/overview/agent-auth-adk), [WIT capabilities](https://docs.terminal3.io/developers/adk/tips/capabilities-from-wit-import).

## What T3N already owns

T3N already provides the substrate for identity, confidential execution, secret isolation, egress restriction, delegation, and platform activity/audit. Building another DID check, private map wrapper, or host allowlist would not be novel. BreakGlass's real application layer is the incident state machine and provider protocol.

## What T3N does not currently own for this problem

The current public surfaces do not prove a host-enforced incident-triggered grant, one-use external effect reservation, provider token exchange, webhook verification, target uniqueness, or a receipt atomically binding cause, authority, action, and outcome. These gaps are the available product layer above the sponsor substrate.

## Version and architecture consequence

The local SDK is newer/wider than the component's WIT world. Types existing in `index.d.ts` are not proof that a registered contract may import or use them. The safe rule for any next design is: only claim capabilities proven by the exact WIT package, node environment, registered contract, and live invocation. A version string in a proof is not a platform receipt.
