Research/retrieval date: 2026-09-01. The purpose is to extract mechanisms and failure handling, not copy enterprise branding.

## Patterns that combine unusually well with T3N

1. A T3N agent DID and private evidence map can replace an application server's bearer session.
2. A signed, attenuated capability can express target/action/purpose without exposing provider secret material.
3. A GitHub App installation token can make provider authority short-lived and repository/permission scoped.
4. A host-stamped T3N activity entry can anchor who invoked what contract and when.
5. A SOAR-style incident state machine can close detection, escalation, recovery, and postmortem.

The missing composition is an effect-safe handoff across T3N's committed state and GitHub's non-transactional API. No adjacent pattern eliminates that seam; each supplies only one side.

## What remains standing in every credible design

Trust roots, App private keys or federation configuration, policy definitions, tenant ownership, webhook secret, provider installation, and the receiver's ability to store dedupe/reservation state all remain standing. “JIT” means the use credential/action is temporary and narrow; it does not mean the organization has no standing root of trust.
